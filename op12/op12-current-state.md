**ROOT CAUSE FOUND — FORCE-LOAD IS THE HARM (2026-09-16, converged w/ lh-laptop + research agent):** The whole force-load approach in [[op12-docker-build-recipe]] is WRONG and causes the bootloop. Mechanism: Docker configs that mutate CORE structs (SYSVIPC/IPC_NS→task_struct; new cgroup SUBSYS→cgroup_subsys_id enum; USER_NS→cred/nsproxy) shift field offsets → symbol CRCs drift (~754 in build B). Neutering check_version/same_magic + MODULE_FORCE_LOAD does NOT fix ABI — it only SILENCES the CRC check, so a stock vendor/GKI module loads and reads/writes at the OLD offsets → memory corruption in early init → silent pre-console reset (= our empty-pstore bootloop). So force-load = active harm. Also: MODULE_SIG_FORCE is OFF → signatures never block (only taint); the system_dlkm EACCES that broke stockA networking was MODULE_SIG_PROTECT/protected-exports, fixed cleanly by `rm -rf common/android/abi_gki_protected_exports_*` (WildKernel's method; == our gki_module.c patch functionally). Our build re-keys (certs/signing_key.pem absent→auto-gen) but that's moot for Image-only shipping once protected-exports deleted. WildKernel loads stock modules w/ ZERO force-load because KSU/SUSFS add NEW subsystems (no core-struct drift) — Docker is harder because it perturbs core structs.

**THE FIX = KABI RESERVE PADDING (DroidSpaces-OSS):** park new struct fields in pre-existing ANDROID_KABI_RESERVE slots so CRCs stay byte-identical under __GENKSYMS__ → enable SYSVIPC/IPC_NS etc. WITHOUT CRC drift → stock modules stay ABI-compatible → NO force-load, keep MODVERSIONS + MODULE_SIG_PROTECT. Tree has the slots: common/include/linux/sched.h = 15 ANDROID_KABI_RESERVE in task_struct; android_kabi.h present. cred.h = 0 slots (watch USER_NS). Patches: github.com/ravindu644/Droidspaces-OSS (Documentation/resources/kernel-patches/GKI/below-kernel-6.12, SYSVIPC kABI patch, try reserve-slot variant 6_7_8 then 3_4_5/1_2_3); guide Documentation/Kernel-Configuration.md.
